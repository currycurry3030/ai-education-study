> 참고: `notes/4_프롬프트엔지니어링.md`의 6. 산출물 제작 전 3가지 Best Practice, HBF 실습 예시(구조가 동일, 주제만 다름)

## ① Blindspot Pass (사각지대 통과) — 모르는 걸 먼저 이해하기

- [ ] **1단계 — 사각지대 파악**: "만들지 마" 제약을 걸고 설명만 요청
  > 스페이스X와 협업해 우주에서 버틸 수 있는 메모리를 만들려고 해. DDR7이 우주 환경(방사선, 극한 온도, 진공)에서도 신뢰성 있게 동작하려면 어떤 기술적 과제가 있는지 설명하는 발표 자료를 만들어야 해. 내가 만들어달라고 직접적으로 말할 때까지 만들지 마. 중학생도 이해할 수 있게 설명을 짧고 쉽게 해줘.
- [ ] **2단계 — 이해 검증**: AI 설명을 읽고 본인 말로 되짚어 확인
  > (예시) "우주는 방사선 때문에 메모리 데이터가 깨지기 쉽고, 온도차도 커서 일반 DDR7이 그대로 못 버틴다는 거지? 내가 이해한 게 맞아? 확실해?"
- [ ] **3단계 — 더 나은 이해(인터랙티브 Web App)**:
  > DDR7과 우주용 메모리(Rad-hard 메모리)의 차이를 쉽게 이해할 수 있는 인터랙티브한 Web App을 만들어줘.

## ② Brainstorms and Prototypes (브레인스토밍과 시안)

- [ ] **브레인스토밍**:
  > 지금부터 브레인스토밍 해볼게. DDR7 우주 환경 신뢰성 발표 자료를 어떤 흐름으로 만들면 좋을까? 개념 설명, 기술적 과제(방사선/온도/진공), 해결 방안, 성능 예측, 결론이 필요할 것 같은데 같이 정리해줘.
- [ ] **Prototypes 요청 (선택지 받기)**:
  > DDR7이 우주 환경에서 신뢰성을 확보하는 방법을 효과적으로 설명할 수 있는 후보 3개를 보여주는 인터랙티브한 Web App을 만들어줘. 후보 1, 2, 3 중 마음에 드는 것을 내가 채팅으로 알려줄게.
- [ ] 후보 하나 선택해 답변 (예: "후보 2가 마음에 드네")

## ③ Interviews (인터뷰) — AI가 나에게 되묻게 하기

- [ ] > 발표 자료를 제작하기 전, 모호한 부분은 한번에 하나씩 질문해줘.
- [ ] AI가 던지는 질문에 하나씩 답변 (예: 발표 대상, 강조하고 싶은 스펙, 스페이스X 협업의 구체적 시나리오 등)

## 발표 자료 제작 지시

- [ ] > 지금까지 대화를 기반으로 발표 자료를 제작해줘. Web 기반, 인터랙티브하게 만들어줘.
- [ ] 완성된 Web App 확인 (URL 또는 html 다운로드)

## ④ Quizzes — 이해도 확인

- [ ] > 발표 자료 내용을 내가 완벽히 이해했는지 확인하는 용도로 O, X 퀴즈 4개를 내줘.
- [ ] 퀴즈 풀어보고 이해도 스스로 점검

## 프롬프트 정리 문서 (제출용 HTML)

- [ ] > 아래는 네 가지 프롬프트 엔지니어링 기법이야. 1. Blindspot Pass: 내가 알지 못하는 부분 설명해달라고 하기 2. Prototypes: 본인이 선택할 수 있는 선택지를 달라고 AI에게 요청한다. 3. Interviews: AI가 본인에게 궁금한 것을 물어보도록 요청한다. 4. Quizzes: 이해도를 높이기 위한 퀴즈를 내달라고 AI에게 요청한다. 위 네 가지 기법 별로, 내가 어떤 프롬프팅을 했었는지 정리한 HTML 문서를 만들어줘.
- [ ] 생성된 HTML 다운로드
